Unofficial demo · not affiliated with TypeSafe AI

Typed decisions, one pass, no parsing

Reproducing the parallel constrained decoding idea behind Jev (TypeSafe AI's "System One" model) on a stock 1.5B model, on a laptop. Instead of generating JSON token-by-token, all schema fields are evaluated in one batched forward pass and the JSON is assembled programmatically — so it can never be malformed.

How it works

[context + schema] ──► prefill (once) ──► KV cache
                                            │ broadcast × N fields
      ┌───────────┬───────────┬─────────────┴───────────┐
    field 1     field 2     ...                      field N
      └───────────┴──── one batched forward pass ────────┘
                          │
              slice logits → softmax → pick value + probability

Does a bigger model help? (measured)

24 labeled cases × 3 fields = 72 decisions per model, same engine. "All fields exact" = every field of the case correct.

Model (4-bit)Primary fieldAll fields exactLatency / case
Qwen2.5-1.5B58% (= majority-class baseline)50%147 ms
Qwen2.5-7B96%72%611 ms
Qwen3-8B92%85%646 ms

Bigger is worth it — but not "biggest wins": 7B for the single decision you act on, 8B when the whole typed payload must be right, 1.5B for demos only. And confidence does not reliably flag errors — the 7B was >90% confident on 13 of its 20 wrong fields. Full breakdown in the GitHub repo.

How does this compare to Jev itself?

TypeSafe published workflow accuracies at evals.typesafe.ai: Jev scores 67.8% mean (61.7–76.0% across four workflows) against a frontier-model consensus (GPT-6 Astra and Fable 5.1 averaged), at $0.0004 and 0.4 s per case.

The accuracy numbers are not equatable: against a frontier consensus our metric would imply beating Opus 5 (73.1%) and Sol (74.1%) on TypeSafe's own eval — implausible for a 4-bit 8B on a laptop. The honest read: same latency class and safety, far cheaper, accuracy unknown against their metric. Full analysis in the GitHub repo.
